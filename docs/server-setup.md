# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины

- Операционная система: Ubuntu Server 24.04.5 LTS
- Оперативная память: 2048 МБ
- Процессоры: 2 ядра
- Диск: 25 ГБ, динамический

## 2. Сетевые интерфейсы

- Адаптер 1: NAT, адрес гостевой системы `10.0.2.15`; используется для исходящего доступа в Интернет.
- Адаптер 2: Host-only, адрес `192.168.56.102`; используется для доступа с хостовой Windows-системы.

## 3. Правило проброса портов

- Протокол: TCP
- Адрес и порт хоста: `127.0.0.1:2222`
- Адрес гостя: не задан
- Порт гостя: `2222`

## 4. Учётные записи

- `student`: локальная учётная запись, входит в группу `sudo`, вход по паролю.
- `devops`: входит в группу `sudo`, SSH-вход по ключу Ed25519.

## 5. Служба SSH

- Порт: `2222/tcp`
- Файл дополнительных настроек: `/etc/ssh/sshd_config.d/99-hardening.conf`
- `PermitRootLogin no`
- `PasswordAuthentication no`
- `PubkeyAuthentication yes`
- `PermitEmptyPasswords no`
- `MaxAuthTries 3`
- `LoginGraceTime 30`
- `AllowUsers devops`
- `X11Forwarding no`
- `ClientAliveInterval 300`
- `ClientAliveCountMax 2`

## 6. Правила межсетевого экрана

- UFW активен.
- Политика входящих соединений: `deny`.
- Политика исходящих соединений: `allow`.
- Разрешён TCP-порт `2222` с ограничением частоты подключений (`limit`).
- Разрешены TCP-порты `80` и `443`.

## 7. Снимки состояния

- `01-clean-install`: после установки Ubuntu Server.
- `02-keys-configured`: создан пользователь `devops`, настроен вход по SSH-ключу.
- `03-ssh-hardened`: усилена конфигурация SSH, настроены правила UFW.
## 8. Веб-сервер, TLS и развёртывание сайта

Установлен и включён Nginx. Сайт `devops.local` размещён в `/var/www/devops-site`; каталог принадлежит `devops:devops`, каталоги имеют права `755`, файлы — `644`. Рабочие процессы Nginx запускаются от `www-data`.

В конфигурации Nginx настроены прослушивание IPv4 и IPv6, перенаправление HTTP на HTTPS кодом `301`, протоколы TLS 1.2 и TLS 1.3, отдельные журналы доступа и ошибок, а также собственная страница `404.html`.

Для HTTPS создан самоподписанный сертификат с SAN `DNS:devops.local` и `IP:192.168.56.102`. Закрытый ключ `/etc/ssl/private/devops.key` имеет права `600`; сертификат `/etc/ssl/certs/devops.crt` — `644`. Клиент WSL проверяет сервер командой `curl --cacert ~/devops.crt https://devops.local`.

Статические файлы `site/index.html` и `site/404.html` развёртываются из ветки `feature/web-deploy` командой `scripts/deploy.sh`. Скрипт проверяет чистоту Git, поддерживает режим `--dry-run`, использует `rsync` с `--delete` и правами `D755,F644`, затем проверяет доступность сайта по HTTPS и записывает хеш коммита в журнал.

Проверка прав показала следующие результаты для каталога сайта: `755` — HTTP 200; `750` и `744` — HTTP 403; `711` — HTTP 200, поскольку Nginx может пройти к известному файлу. При правах `600` у `index.html` Nginx возвращает HTTP 403. Разрешение записи позволило пользователю `www-data` изменить файл; повторное развёртывание восстановило содержимое и права.

Запросы к `/.env` и `/wp-login.php` зарегистрированы в журнале и получили HTTP 404. Это означает, что запрошенные ресурсы отсутствуют. Журнал позволяет определить адрес клиента, путь, код ответа и клиентскую программу.

Созданы контрольные снимки VM `04-nginx-https` и `05-rsync-deployed`.
